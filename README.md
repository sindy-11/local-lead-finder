# LOCAL LEAD FINDER

Локальное приложение для поиска публичных карточек бизнеса, ручной проверки, сохранения лидов и ведения CRM. Никаких рассылок или автоматических звонков. Для основной работы OpenAI не нужен.

## 1. Установите Node.js

Скачайте **Node.js 24 LTS** с https://nodejs.org/en/download, установите с настройками по умолчанию. Закройте и снова откройте PowerShell. Проверьте:

```powershell
node --version
npm --version
```

## 2. Откройте папку и установите зависимости

```powershell

npm install
```

Если PowerShell запрещает npm.ps1, используйте `npm.cmd` вместо `npm` (например, `npm.cmd install`). Не нужно менять системную execution policy.

## 3. Создайте .env.local

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

Содержимое для начала:

```dotenv
GOOGLE_PLACES_API_KEY=
DATABASE_URL=
```

Пустой ключ означает, что LIVE-поиск не настроен. DEMO работает без ключа. SQLite по умолчанию использует `prisma/leads.db`. При необходимости задайте DATABASE_URL=file:./leads.db (путь относительно prisma/). Не добавляйте префикс NEXT_PUBLIC_ к ключу. Не публикуйте .env.local: `.gitignore` исключает все .env-файлы, кроме пустого .env.example.

## 4. Создайте SQLite database

Не требуется отдельный сервер базы данных.

```powershell
npm run db:generate
npm run db:migrate
```

В проекте есть готовая начальная миграция. Команда `db:migrate` применит её к `prisma/leads.db`. При изменении schema разработчиком:

```powershell
npm run db:dev -- --name your_change
```

## 5. Запустите приложение

```powershell

```

Откройте http://127.0.0.1:3000. Оставьте PowerShell открытым. Для остановки нажмите Ctrl+C. Приложение доступно только с вашего компьютера. Если порт занят:

```powershell

```

Для production build:

```powershell

```

## 7. Подключите LIVE Google Places API

1. Откройте https://console.cloud.google.com/ и войдите в Google account.
2. В верхнем списке проектов нажмите «New project», задайте название, создайте и выберите проект.
3. Подключите **Billing** для этого проекта. API может тарифицироваться.
4. Откройте **APIs & Services → Library**, найдите **Places API (New)** и нажмите Enable.
5. В **APIs & Services → Credentials → Create credentials → API key** создайте ключ.
6. Откройте настройки ключа. В API restrictions выберите **Restrict key → Places API (New)**. Это серверный REST API: ограничение HTTP referrers для него не подходит. Если есть фиксированный публичный исходящий IP сервера, задайте **IP addresses**. Для домашнего динамического IP следите за актуальным адресом; не считайте 127.0.0.1 публичным IP.
7. Установите квоты Places API в Cloud Console. Настройте budget alerts. Budget alert сам по себе не блокирует расходы.
8. Откройте .env.local и вставьте ключ после знака равно:

```dotenv
GOOGLE_PLACES_API_KEY=вставьте_свой_ключ_здесь
DATABASE_URL=
```

9. Остановите приложение Ctrl+C и снова выполните `npm run dev` или `npm start` для готового build.
10. Откройте Settings: статус должен быть Configured. Выберите **LIVE DATA**, введите город, категорию, количество и запустите поиск.

Ключ никогда не отправляется в браузер, не сохраняется в SQLite и не печатается в логах. Если Google отклоняет запрос, проверьте ключ, Places API (New), billing и ограничения. Если запрос успешен, но результатов нет, попробуйте другую категорию или город. Поиск принимает название города, но не выполняет отдельную платную геокодирующую проверку: неоднозначное название может дать неожиданные результаты, проверьте адреса.

Документация API: https://developers.google.com/maps/documentation/places/web-service/text-search

## 8. Стоимость и ограничения

Перед поиском интерфейс показывает максимальное число Text Search запросов: `ceil(limit / 20)`. Максимум 100 запрашиваемых бизнесов и 5 страниц. Количество результатов не гарантируется; это предел, а не обещание числа подходящих лидов. Google может вернуть меньше; фильтр «Potential leads» применяется после поиска.

Телефон, website, rating и reviews запрашиваются в field mask Text Search и могут активировать более дорогой SKU. Здесь нет скрытых Place Details запросов. Актуальные тарифы проверьте: https://developers.google.com/maps/billing-and-pricing/pricing

Защита сервера: один LIVE-поиск одновременно, максимум 5 поисков в минуту и 100 зарезервированных API-операций за день на процесс. Лимиты в памяти сбрасываются при перезапуске; квоты Google Cloud нужны для жёсткой защиты. В случае ошибки уже использованные API-запросы могут тарифицироваться. Автоматических повторных запросов нет. Timeout одной операции — 20 секунд.

## 9. Сохранение и ручная CRM

Нажмите иконку закладки в таблице либо откройте бизнес через название/стрелку. В панели:

- Save lead & changes сохраняет лид, заметки и введённые контакты.
- Contact status: NEW, TO CONTACT, CONTACTED, REPLIED, INTERESTED, NOT INTERESTED, FOLLOW UP, CLIENT.
- Mark as contacted меняет статус на CONTACTED и сохраняет форму.
- Notes — ваши заметки, например «Написал 01.10; ответили через неделю».
- Instagram URL, WhatsApp, Email и другие ручные поля не заполняются автоматически.
- VERIFIED NO OFFICIAL WEBSITE требует заметку с основанием проверки. Отсутствие website в API означает только NO WEBSITE LISTED.
- Убрать из сохранённых удаляет закладку, но сохраняет историю CRM и заметки.

Dashboard читает записи из SQLite. FOUND — число уникальных Place ID, не сумма повторных выдач. CONTACTED — все статусы после NEW/TO CONTACT; REPLIED/INTERESTED/CLIENTS — текущие соответствующие статусы, не история переходов. Закрытые навсегда бизнесы не считаются potential leads.

Score — понятная сортировка: +3 website не указан, +2 телефон, +2 reviews ≥50, +1 rating ≥4, +1 Operational. Формула видна под таблицей. Это не прогноз продажи.

## 10. Особенность данных Google и экспорта

Политика Google ограничивает постоянное хранение данных Places, кроме разрешённых исключений, в том числе Place ID: https://developers.google.com/maps/documentation/places/web-service/policies

**Поэтому приложение не сохраняет Google business name, phone, address, website, rating, reviews, координаты или производные признаки в SQLite.** Они доступны в памяти страницы после поиска. Сохраняются Place ID, источник, ваша история поиска и собственные CRM-поля. После перезагрузки LIVE-карточки отображают Place ID и ручные поля; откройте Maps или явно выполните новый поиск для получения данных. Автоматического платного обновления нет. NO WEBSITE LISTED в LIVE-dashboard показывает «—», поскольку этот признак не хранится.

CSV и Excel экспортируют текущие отфильтрованные строки. DEMO экспортирует все колонки. LIVE экспортирует Place ID и ваши ручные CRM-поля: колонки Google остаются пустыми. Не копируйте Google-контент в ручные поля с целью обхода ограничений. Для будущего провайдера, разрешающего хранение и экспорт, есть интерфейс `PlacesProvider`.

**CSV**: UTF-8 с BOM и разделитель `;` для кириллицы/Excel. Если ваша локаль Excel не распознала разделитель, выберите «Данные → Из текста/CSV», UTF-8 и точку с запятой. Значения, похожие на формулы, экранируются апострофом. Телефоны сохраняются текстом. **XLSX** открывается непосредственно в Excel, с заголовками и фильтрами.

Откройте Templates, вставьте URL для BARBERSHOP, TATTOO и других категорий, нажмите Save URL. Ссылки сохраняются в SQLite. ## 12. Backup и восстановление

Остановите приложение Ctrl+C перед backup, чтобы база не изменялась во время копирования:

```powershell
npm run db:backup
```

Копия появится в `backups`. Дополнительно сохраните `.env.local` отдельно в безопасном месте: ключ не входит в backup БД. Для восстановления остановите приложение, сделайте копию текущей базы и замените prisma/leads.db вашей копией:

```powershell
Copy-Item "backups\имя_вашей_копии.db" "prisma\leads.db" -Force
npm start
```

## 13. Проверка и обновление

Остановите приложение, сделайте backup, сохраните .env.local и prisma/leads.db. Получите новые файлы проекта, не заменяя базу и секреты. Затем:

```powershell
npm ci
npm run db:generate
npm run db:migrate
npm run typecheck
npm run lint
npm test
npm run build
npm start
```

`npm ci` использует проверенный package-lock.json. Не запускайте миграции с reset против важной базы. Не применяйте `npm audit fix --force` без анализа несовместимых обновлений.

## Структура

```text
app/              страницы и server API routes
components/       workspace и карточка лида
db/               серверный Prisma client
lib/              validation, score, export, защита запросов
providers/        Google Places, demo, интерфейсы enrichment
services/         поиск/сохранение и будущий необязательный AI adapter
prisma/           schema, migrations и локальная SQLite database
types/            общие типы
scripts/          backup
tests/            проверки score, validation, demo и CSV
```

Приложение рассчитано на одного локального пользователя. Для публичного размещения понадобятся авторизация, HTTPS, постоянное ограничение расходов, подходящее хранилище и публично доступные terms/privacy. Сейчас /terms и /privacy доступны локально; перед публичным использованием Google разместите их по публичному URL. Не выставляйте локальную CRM в интернет без этих изменений.


На Windows остановите приложение перед db:generate, иначе DLL Prisma может быть занята (EPERM).

Для повторной HTTP-проверки запустите приложение на порту 3011 и выполните npm run test:smoke. Тест создаёт собственный demo-поиск, проверяет CRM и экспорт и удаляет свои записи после успешного завершения. Он рассчитан на отсутствие Google API key.

В этой среде порт 3000 занят: готовое приложение запущено на http://127.0.0.1:3011. Для такого же запуска используйте npm start -- --port 3011.
